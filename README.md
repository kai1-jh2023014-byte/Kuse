# KUSE

過去に作ったデザインから、その人の色・構図・余白・文字の置き方の癖を読み取り、Canva AI にそのまま貼れる指示文を作る Web アプリです。

一般的な「きれいな案」より、「この人が作ったように見える」ことを優先します。

## 概要

発表スライドやポスターを、テンプレートの見た目だけで揃えると、誰が作っても同じになります。KUSE は、先に自分の作品を見せて「いつもやっていること」を測り、その癖を Canva への指示文にします。

原稿は1枚ずつ切らず、通しで貼ります。相手の感情が動く順番、力を入れる枚と控える枚、切り替えで足す一行、画像・動画・効果音の置き場まで含めて、スライドの役を決めます。Canva へ渡したあとは、保存した癖への近さ（出来の点数ではない）を見て、届くまで生成を最大3回まで繰り返します。

画像ファイルはサーバーに保存しません。作品とプロファイルはブラウザの IndexedDB に残ります。Canva のトークンはサーバー側だけに置きます。

## 誰向けか

- 自分の過去作を土台に、次のスライドやポスターを作りたい人
- Canva AI に渡す文章を、感覚ではなく自分の癖から書きたい人
- 原稿はあるが、1枚ごとの役（表紙、共感、並列、インパクト、着地）が決まっていない人

## 技術

| 層 | 内容 |
| --- | --- |
| 画面 | Next.js App Router、React、Tailwind、shadcn/ui |
| 分析 | クライアントで縮小した画像のピクセル計測。任意で OpenAI 互換のビジョン |
| Canva | 公式 MCP（OAuth + PKCE）。ブラウザ自動化は使わない |
| 素材検索 | ユーザーが指示したときだけ Wikimedia Commons。作者・ライセンス・URL を書く |
| 起動 | `npm run dev`（ポート 3847）。`npm run install-shortcut` でデスクトップから開く |

## できること

1. 複数のデザインをドラッグ＆ドロップ、フォルダ、PDF、ZIP、PowerPoint から置く（最大200点）
2. 画像から色、明度、余白、構図、密度を計測する
3. 作品を横断して、繰り返している行動を「デザインの癖」として保存する
4. 1枚だけでは癖と断定せず、確信度（何点中何点か）を残す
5. 新しい作品を足したとき、過去の傾向を消さずに更新する
6. 作りたいものの目的と、自分らしさの強さ（0〜100）から Canva AI 用プロンプトを生成する
7. 通しの原稿を貼ると、感情が動く境目でスライドに分け、確認してから切り直せる
8. ワンクリックでコピーし、「余白を増やす」などの指示で再生成する
9. Canvaアカウントを公式OAuthで接続し、プロンプトからデザイン候補を生成する

データはブラウザの IndexedDB に残ります。サーバーは画像を保存しません。

## 起動

```bash
npm install
npm run dev
```

ブラウザで [http://127.0.0.1:3847](http://127.0.0.1:3847) を開きます。

APIキーが無くても動きます。その場合は、画像ピクセルの計測と、複数作品の比較だけでプロファイルとプロンプトを作ります。

## デスクトップショートカット

このパソコンのデスクトップから、ブラウザのタブではなくアプリ窓として開きます。

```bash
npm install
npm run install-shortcut
```

デスクトップに `KUSE.bat` が置かれます。ダブルクリックすると黒い窓が開き、その窓の中で開発サーバーが動きます。`Ready` やコンパイルの行が出るのが正常です。Chrome または Edge を `--app` で開きます。設定と Canva の接続はユーザーフォルダの `.kuse` に作ります。リポジトリに `.env.local` が無いときは、起動時に作ります。すでに 3847 番で動いている古い窓がある場合は、それを閉じてから開き直してください。黒い窓を閉じると、このショートカットから起こしたサーバーは止まります。

**Windows で何も起きないとき**

1. リポジトリのフォルダで、先に `npm install` を一度実行する
2. もう一度 `npm run install-shortcut` して、デスクトップの `KUSE.bat` を作り直す
3. その `KUSE.bat` をダブルクリックする。失敗すると窓が残るので、メッセージを読む
4. ログは `%TEMP%\kuse-launch.log` に書きます

古い `KUSE.bat` は、失敗してもすぐ窓が閉じるため、何も変わっていないように見えます。作り直したあとのファイルを使ってください。

ショートカットを置かずに今すぐ開くときは `npm run desktop` です。

Chrome や Edge で開いたあとに、アドレスバーの「アプリとしてインストール」でも、同じ画面をスタンドアロン窓にできます。その場合も、中身を出すにはこのリポジトリのサーバーが起動している必要があります。

## 使い方

### 1. 学ぶ

自分のポスター、サムネイル、投稿画像、PDF、スライド資料、フォルダごとを置きます。2点以上あると、共通点を癖として扱います。200点までブラウザに残します。

手元に作品が無いときは「見本の作品で試す」で、同じ癖を持つ4点を置けます。これは分析の動作確認用です。

「デザインを分析する」を押すと、次を順に見ます。

- 色と明暗
- 余白、構図、密度
- 作品同士の共通点
- 無意識の癖の言語化

### 2. スタイル

カラー、レイアウト、タイポグラフィ、ビジュアル、印象、デザインの癖、避けること、新しく見つかった特徴を表示します。内部の JSON も開けます。

作品を削除すると、残った作品だけで傾向を組み直します。傾向は固定ではなく、新しい作品が入ると少しずつ動きます。

### 3. つくる

目的、ターゲット、掲載する文字、サイズ、雰囲気、入れたい画像を書きます。

自分らしさ:

| 値 | 意味 |
| --- | --- |
| 0 | 一般的なデザイン |
| 25 | 少し自分らしく |
| 50 | 自分のスタイルを反映 |
| 75 | 強く自分らしく |
| 100 | できる限り自分のデザインスタイルを再現 |

生成された文章の「コピー」で全文をクリップボードへ送ります。追加指示は、既存の癖を土台にしたまま差分として重ねます。

### 4. 役割

スライドは、1枚の見た目より、全体で何を残したいかと、相手の感情がどう動くかが先です。「役割」では原稿を一枚ずつ貼らず、通しの文章をまとめて貼ります。「流れを読んで分ける」と、残したい一文だけを山にし、前後の説明はまとめて力を入れない枚にします。役は表紙・感情の先回り・並列・インパクト・着地です。強弱は 控 / 揃 / 力 で、力を入れる枚は全体で一つです。

- 表紙は説明を始めず、関係があると感じさせる
- 相手が既に思っていることは、「みなさんはきっとこう思ってますよね」と先に言う
- 並べて見比べる内容は、同じ強さで同時に置く
- 重要な一点は、周囲を空けて一度だけ大きく動かす
- 最後は要約ではなく、持って帰る気持ちを一つ残す
- 前提と結論を1枚に載せない。前の枚の配置を保ち、結論だけを次の枚の切り替えで足す。矢印（⇓）や「だから」「と、」で分かれる説明は、二枚になる
- 各枚に、画像・動画・効果音を置くか置かないかを先に決める。言葉が山の枚には写真を重ねない。切り替えで要素が出る瞬間だけ、効果音を一つ鳴らす。効果音のファイルは自動では取らない
- 「ネットから探す」か、監査にその指示を書いたときだけ、画像と動画を Wikimedia Commons から探す。一文字だけの語では探さない。動画は、ファイル名か説明にその語があるときだけ出典を付ける。取った素材は作者・ライセンス・出典URLをスライドに書く。原稿に動画や画像のURLが書いてあるときは、そのリンクを出典にして、ファイル自体は取りにいかない

分けた結果は、右側で確認します。違うところは「この分け方への監査」に書いて「監査を反映して、もう一度分ける」を押すと、同じ原稿を切り直して、また確認に戻ります。自動では次の枚へ進みません。言葉だけ直した場合は「この分け方で役割を見なおす」で役だけ更新します。

「この役割でプロンプトを作る」を押すと、その役が【このスライドの役割】として、レイアウトより前に入ります。色や余白の癖は今までどおり後ろに続きます。原稿を書き換えたあとは、もう一度流れから分けます。

モデルのキーがあるときは、原稿にある文だけを使って境目を提案します。キーが無いとき、またはモデルの結果が原稿から外れたときは、文の切れ目と感情の合図で分けます。

### 5. Canva

「Canva」から、今のプロンプトを Canva 公式 MCP の **Canva AI**（`create-design`）へ渡します。これはフラットな画像生成（`generate-image`）ではありません。スライド、ロゴ、YouTubeサムネイルなどは `format` を付けて自然文のブリーフごと送り、`get-create-design-async-job` で完了まで待ちます。接続に `create-design` が無いときだけ、古い `generate-design`（候補プレビュー）に戻します。

1. 「Canvaと接続」を押す。クライアントIDの手入力は不要です
2. 接続トークンはユーザーフォルダの `.kuse` に残ります
3. Canva の画面で自分のアカウントを認可する
4. 「Canvaで生成」のあと、返った候補から使うものを選ぶ

「基準まで自動で作る」と「Canvaで作る」は、プロンプト全文を公式の create-design（なければ generate-design）に渡し、保存した癖への近さを測ります。高い優先度のずれが残る間は改善プロンプトで新しいデザインを作り、最大3回です。基準に届く前の回は畳んでおき、届いた結果だけを先に出します。これは出来の点数ではなく、KUSEスタイル一致度です。プロファイルが無いときは測れないので、最初の結果を表示します。

批評を書いて「この批評で、もう一度回す」と、その文を改善に入れて、また最大3回回します。既存デザインの中身を自然文で書き換える公式の引数は、接続中のツールから確認できないため呼びません。

`create-design` が編集可能なデザインを返したときは、その場で Canva 上のデザインとして扱います。古い `generate-design` の候補だけが返ったときは、選んだ候補を `create-design-from-candidate` でデザインにします。編集の確定は Canva の画面で行います。

公式ドキュメントでは、Developer Portal からの MCP 自己発行がまだ使えない場合があります。KUSE は接続時に MCP 用クライアントを登録するので、画面が env 未設定にはなりません。生成成功は、本物のトークンが返ったときだけです。

アクセストークンはブラウザに置きません。このパソコンの `.kuse` フォルダにだけ残し、git には含まれません。

生成されたデザインは、ユーザーが「自分らしい」と承認するまで学習データにしません。

### 6. 生成結果の評価

Canva の候補が出たあと、「KUSE分析」でその画像を測ります。

- 色、余白、コントラスト、揃えはピクセル計測が優先です
- ビジョンモデルが使えるときだけ、構図・文字の関係・密度・視線の文章を足します
- **KUSEスタイル一致度**は、保存した design_profile との近さです。デザインの出来ではありません
- 一致している部分は残し、ずれだけを直す改善プロンプトを作ります
- 「Canvaで改善版を生成」は、その文章で新しい候補を1回だけ作ります。既存デザインの自動編集はしません
- 「このデザインは自分らしい」と「ここが違う」は、次の改善プロンプトに入ります
- 「このデザインを自分のスタイルとして学習」は候補を出すだけです。承認した特徴だけを design_profile に足します

Version が2つあるときは、左右にサムネイルと KUSEスタイル一致度を並べます。

## 開発メモ

### 追加した機能

- `planSlideRoles()` — スライド全体の感情の順番と、1枚ごとの役割
- `evaluateGeneratedDesign()` — 生成画像の計測値と design_profile の比較
- `generateImprovementPrompt()` — 維持と修正を分けた Canva 用の改善文
- 評価、フィードバック、学習候補、1回だけの改善生成を Canva 画面に表示

### Canva API でできること

- OAuth（認可コード + PKCE）で本人のアカウントに接続する
- `tools/list` のスキーマに沿って、先に `create-design`（Canva AI）を呼ぶ。無ければ `generate-design`
- `get-create-design-async-job` / `get-generate-design-async-job` で完了まで待つ
- 返ったデザインまたは候補の ID、URL、サムネイルを受け取る
- まだ候補のままのとき、ユーザーが選んだものを `create-design-from-candidate` でデザインにする
- 改善プロンプトでもう一度 `create-design`（または `generate-design`）を呼ぶ
- `generate-image` は使わない（コピー付きレイアウトを一枚絵として出す経路のため）

### Canva API の制約

- `POST /v1/designs` は自然文のプロンプトを受け取れない
- 候補を Canva のデザインにする操作は自動では行わない。近さの計測に使うサムネイルだけ、いちばんプロファイルに近いものを選ぶ
- サムネイル URL は短命で、期限が切れると再計測できない
- `perform-editing-operations` は構造化された編集操作であり、改善プロンプトをそのまま渡す引数は接続中のスキーマから確認できない。確認できない編集は呼ばない
- 生成の自動ループは、新しいデザインを `create-design`（フォールバックは `generate-design`）で最大3回作るところまで。既存デザインの中身を書き換える編集は、引数が未確定のため呼ばない

### 今後の自動化候補

- 編集ツールの inputSchema に、デザインIDと自然文を一意に入れられる欄が出たら、その欄だけを使って既存デザインを更新する
- サムネイルが期限切れになる前に、計測済みの数値を評価の再計算に使う（数値は保存済み）
- 編集が公式に可能になってから、既存デザインそのものを更新するループに切り替える

## AIの差し替え

AIの入出力は `src/services/ai/` に閉じ込めています。

- `DesignAnalyzer` — 計測値からプロファイルを作る。キーがあるときはビジョンモデルで言語化を足す
- `StyleProfileManager` — 複数作品の比較、確信度、過去プロファイルとの差分
- `PromptGenerator` — Canva 向けの自然文と、追加指示での再生成。スライドの役割があるときは、装飾より先にその役を書く
- `CanvaService` — Canva MCP との OAuth と、create-design / generate-design / create-design-from-candidate
- `DesignEvaluator` — 生成結果と design_profile の一致度。品質点ではない
- `ImprovementGenerator` — 一致部分を残す改善プロンプト
- `IterationManager` — 既存デザインの連続編集は未実装。手作業の「Canvaで改善版を生成」は1回まで
- `runGenerationLoop()` — 公式の生成、近さの計測、改善プロンプトでの再生成を最大3回。基準に届いた版だけを表示する
- `FeedbackManager` — 画面のフィードバックはバージョンに保存し、次の改善文へ渡す

画像の数値は常にピクセル計測が源です。モデルは文章と、計測では拾いにくい印象を足す役で、HEXや支持数を上書きしません。

別のAPIに替えるときは `src/services/ai/provider.ts` を差し替えてください。呼び出し側の画面は変えずに済みます。

```env
AI_PROVIDER=auto
OPENAI_API_KEY=
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini

CANVA_CLIENT_ID=
CANVA_CLIENT_SECRET=
CANVA_REDIRECT_URI=http://127.0.0.1:3847/api/canva/callback
```

`AI_PROVIDER=heuristic` にすると、キーがあっても計測だけを使います。`openai` または `auto` でキーがあるとき、分析用の小さいサムネイルをそのAPIへ送ります。
